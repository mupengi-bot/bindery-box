원칙: **형님 DM은 escalation 채널**. 일상 운영은 #부스설치-철수-일정에서 끝낸다.

### 3.2 HEARTBEAT.md 추가 항목 (제안)

기존 1~11번에 다음을 묶어 넣거나, "포토부스 운영 블록" 하나로 신설:

```
12. 포토부스 운영 오토파일럿 (1일 1회, 오전 트리거)
    a. ERP events: 종료일 < today 인데 status ∈ {inquiry, confirmed} → 후보 리스트 → #부스설치-철수-일정 1줄 요약 푸시
    b. ERP events D-3/D-1: 체크리스트(프레임 마감, 라우터/용지/장비, 담당자 연락, 차량, 결제방식) → #부스설치-철수-일정
    c. ERP events D-day: 아침 06:00 트리거 — 설치 담당/도착예정/하드웨어 풀세트 컨펌 요청
    d. ERP events D+1: 정산·세금계산서·사진 zip·장비 회수 4종 체크 → #부스설치-철수-일정
    e. ERP inquiries received > 7일 → #부스설치-철수-일정에 "콜백 미처리 N건" + 형님 의사결정 필요 라벨
    f. 재고 임계치: 라우터 가용 < 다음 7일 필요량 / 우드부스 용지 < 150장 / 일반 용지 < 200장 → 알림
    g. 캘린더↔ERP unmatched 행사 발견 시 알림 (audit 자동화)
```

### 3.3 ERP 키 데이터 모델 보강 (안)

ERP events에 다음 필드가 필요(또는 활용):
- `frameDeadline` (행사 -2일 자동 계산)
- `routerNeeded` / `routerAssigned` / `paperLevel`
- `installAssignee` / `teardownAssignee`
- `paymentMethod` / `taxInvoiceStatus`
- `onsiteSheetUrl` (memory/templates/onsite-records/*.md 링크)

없으면 events.notes에 JSON blob으로 박아 넣는 것도 가능. 자동화 신뢰성을 위해 정식 필드화 권장.

### 3.4 트러블 1차 진단 자동 응답봇 (Phase 2)

- 트리거: 현장 인원이 #부스설치-철수-일정에 "안 돼요/안 됩니다/안 잡혀요/카드결제기/와이파이/라우터" 키워드 포함 메시지.
- 봇 응답: SOP v1 3가지 항목(`iptime 소프트웨어`, `USB 포트/COM 번호`, `라우터 풀세트`) 체크리스트 + "다 돌렸으면 결과 보고" 1줄.
- 무펭이가 직접 응답(서브에이전트). 형님 호출은 SOP 다 돌리고도 안 됐다고 보고했을 때만.
