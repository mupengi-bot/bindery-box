# Domain Model

This document defines the canonical BINDERY BOX platform entities. The current Alpha scaffold can keep demo-shaped code temporarily, but all platform work should migrate toward these domain concepts.


## Entity Definitions

### Tenant

A customer company or isolated commercial account.

Required fields:

```txt
id
name
slug
status
createdAt
updatedAt
```

Rules:

- Tenant boundaries are security boundaries.
- No workspace, connector, task, or audit record should exist without tenant ownership.

### Workspace

A company, department, project, or operating room inside a tenant.

Required fields:

```txt
id
tenantId
name
slug
editionId
status
createdAt
updatedAt
```

Rules:

- A workspace maps to an Office surface such as a Mattermost team.
- Policies can be applied at tenant and workspace levels.

### HumanUser

A real person using Mission Control, Mattermost, or desktop surfaces.

Required fields:

```txt
id
tenantId
displayName
role
externalIdentityRefs
status
```

Rules:

- Approval decisions must reference a HumanUser.
- Human users may have multiple external identities.

### AgentDefinition

A reusable template for an AI staff role.

Required fields:

```txt
id
editionId
name
role
version
instructionsRef
defaultCapabilities
defaultPolicies
```

Rules:

- AgentDefinition is not a running staff member.
- It belongs to core product, an edition, or a tenant custom library.

### AgentInstance

A deployed staff member in a workspace.

Required fields:

```txt
id
workspaceId
definitionId
name
status
capabilityGrants
officeIdentityRef
createdAt
updatedAt
```

Rules:

- AgentInstance is what appears in Mattermost and Mission Control.
- Task runs are assigned to AgentInstance, not AgentDefinition.

### Capability

A named permission for an action class.

Examples:

```txt
files.read
files.write
email.draft
email.send
mattermost.post
github.issue.create
erp.order.read
connector.record.read
artifact.report.generate
external.customer.send
```

Rules:

- Runtime tool calls must map to one or more capabilities.
- Missing capability means blocked by default.

### Connector

A package describing how the platform integrates with a system.

Required fields:

```txt
id
name
version
capabilities
configSchema
secretRequirements
```

Rules:

- Connector packages are reusable.
- They do not store tenant-specific credentials.

### ConnectorInstallation

Tenant/workspace-specific connector configuration.

Required fields:

```txt
id
workspaceId
connectorId
status
configRef
secretRefs
installedBy
installedAt
```

Rules:

- Installation references secrets; it does not expose raw secret values.

### Task

A unit of work visible to users.

Required fields:

```txt
id
workspaceId
title
description
status
assignedAgentId
priority
createdBy
createdAt
updatedAt
```

Rules:

- Task is the business-level work item.
- A Task may have many TaskRuns.

### TaskRun

One execution attempt for a Task.

Required fields:

```txt
id
taskId
workspaceId
agentId
status
startedAt
completedAt
resultSummary
error
```

Rules:

- Tool calls and approvals attach to TaskRun.
- Retrying a task creates a new TaskRun.

### ToolCall

A concrete attempt to use a tool or connector.

Required fields:

```txt
id
taskRunId
workspaceId
agentId
connectorInstallationId
toolName
capabilities
status
inputPreviewRef
outputPreviewRef
createdAt
completedAt
```

Rules:

- ToolCall must be audited.
- ToolCall can be blocked, pending approval, executed, or failed.

### ApprovalRequest

A human decision required by policy before a sensitive action.

Required fields:

```txt
id
workspaceId
taskRunId
toolCallId
policyRuleId
reason
status
requestedByAgentId
decidedByUserId
decision
createdAt
decidedAt
```

Rules:

- ApprovalRequest is generated by policy, not manually by UI.
- Approval must show the exact action and preview that will be allowed.

### AuditEvent

Append-only record of important system and human actions.

Required fields:

```txt
id
tenantId
workspaceId
actorType
actorId
eventType
subjectType
subjectId
summary
metadataRef
createdAt
```

Rules:

- Append-only.
- No raw secrets.
- All mutations should produce audit events.

### KnowledgeDocument

A source artifact ingested into the workspace memory/knowledge layer.

Required fields:

```txt
id
workspaceId
sourceType
sourceRef
title
status
hash
createdAt
updatedAt
```

### KnowledgeNode

A structured node extracted from documents, decisions, tasks, customers, projects, or operational facts.

Required fields:

```txt
id
workspaceId
documentId
nodeType
title
properties
relations
```

### SecretReference

A reference to a secret managed by local, appliance, or hosted secret storage.

Required fields:

```txt
id
tenantId
workspaceId
provider
keyRef
createdAt
updatedAt
```

Rules:

- Never expose raw secret values in export, logs, audit metadata, or public repo.

### Deployment

A running install of the platform.

Required fields:

```txt
id
tenantId
mode
version
services
health
createdAt
updatedAt
```

Modes:

```txt
local-dev
local-desktop
on-prem-appliance
hosted
hybrid
```

### License

Commercial entitlement for a tenant/deployment.

Required fields:

```txt
id
tenantId
plan
seats
agentLimit
connectorLimit
expiresAt
status
```

## Relationships

```txt
Tenant 1 ── n Workspace
Tenant 1 ── n HumanUser
Workspace 1 ── n AgentInstance
AgentDefinition 1 ── n AgentInstance
Workspace 1 ── n ConnectorInstallation
Connector 1 ── n ConnectorInstallation
ConnectorInstallation 1 ── n CapabilityGrant
Workspace 1 ── n Task
Task 1 ── n TaskRun
AgentInstance 1 ── n TaskRun
TaskRun 1 ── n ToolCall
ToolCall 0 ── n ApprovalRequest
Every mutating action ── n AuditEvent
Workspace 1 ── n KnowledgeDocument
KnowledgeDocument 1 ── n KnowledgeNode
```

## Non-Negotiable Rules

1. `AgentDefinition` is a template; `AgentInstance` is a deployed staff member.
2. `Connector` is a reusable integration package; `ConnectorInstallation` is workspace-specific.
3. `Capability` must be granted before a tool call can execute.
4. `ApprovalRequest` is generated by policy, not directly by UI.
5. `AuditEvent` is append-only.
6. `SecretReference` never stores raw values in public logs, exports, or UI previews.
7. Industry presets must not become hardcoded global behavior.
