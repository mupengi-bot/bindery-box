BINDERY BOX / MUFI Box
제품·웹서비스·데스크톱 개발 설계서

Mattermost 사무실, Mission Control 웹 대시보드, 로컬 멀티에이전트 런타임, Electron/Tauri 데스크톱 런처를 하나로 묶는 화이트라벨 AI Company-in-a-Box 공식 서비스 개발 계획.

제품 정의

BINDERY BOX는 고객사 내부망 또는 클라우드에 작은 AI 회사를 설치하는 운영 플랫폼이다. 사용자는 추상 CLI가 아니라 “직원처럼 보이는 에이전트 팀”을 Mattermost 사무실과 웹 대시보드에서 운영한다.

01. 공식 서비스 포지셔닝: CLI가 아니라 “보이는 회사”

기존 에이전트 제품의 문제

  • CLI/프롬프트 중심이라 비개발자에게 가치가 보이지 않음
  • 에이전트가 실제로 무엇을 했는지 추적하기 어려움
  • 권한, 승인, 비용, 감사 로그가 뒤늦게 붙음
  • 고객사별 화이트라벨/온프레미스 패키징이 약함

BINDERY BOX 해법

  • Mattermost: AI 직원들이 근무하는 사무실
  • Mission Control: 대표/관리자용 통제판
  • Runtime: 실제 도구 실행, 문서 처리, 자동화 엔진
  • Desktop Launcher: 설치·업데이트·권한·로컬 파일 연결
공식 제품명은 외부 판매용 BINDERY BOX, MUFI 생태계 내부명은 MUFI Box로 분리한다. GitHub 리포는 mupengi-bot/bindery-box 또는 mupengi-bot/mufi-box가 적합하다.

02. 업그레이드된 제품 구성

1) Company Office

Mattermost 기반 채널, DM, 승인방, 파일 공유, 회의록. 에이전트가 직원처럼 보여야 한다.

2) Mission Control

조직도, 업무 큐, 에이전트 상태, 승인 요청, 비용, 로그, KPI를 시각화한다.

3) Agent Runtime

프로필별 에이전트, 도구 실행, 지식 검색, 스케줄러, 브라우저/파일/CLI 자동화.

4) Connector Hub

GitHub, Drive, Notion, ERP/MES, Email, Calendar, Excel/CSV, Webhook, MCP 연결.

5) Knowledge Graph

문서, 고객, 프로젝트, 결정사항, 이슈, 탄소데이터, 소스코드 관계망.

6) Desktop Launcher

로컬 실행, 자동 업데이트, 폴더 권한, 키체인/시크릿, 백그라운드 서비스 관리.

05. Electron/Tauri 앱 초안 설계

추천: Tauri 우선, Electron 대안

로컬 파일 권한, 트레이, 자동 업데이트, 포트 점검, Docker 실행 상태 관리가 핵심이므로 데스크톱 껍데기가 필요하다. 단, 무겁게 시작하지 말고 웹 대시보드를 감싸는 런처로 시작한다.

  • Tauri: 가볍고 설치 파일 작음
  • Electron: 웹 생태계 성숙, 개발 빠름
  • MVP는 웹 + CLI, v1.5에서 데스크톱 런처

데스크톱 앱 책임

  • 로컬 런타임 start/stop/restart
  • Docker Desktop/Colima/내장 런타임 감지
  • 로컬 폴더 연결 및 권한 확인
  • 시크릿 저장소 접근
  • 업데이트/로그 수집/진단 리포트
  • 웹 대시보드와 Mattermost 열기
버전배포 형태장점리스크
MVPCLI + Docker Compose + Web빠름, 검증 쉬움, 서버 배포 가능일반 고객에게 설치감 약함
v1.5Tauri/Electron Launcher제품감, 로컬 권한 관리, 트레이서명/업데이트/OS 권한 이슈
v2Managed Cloud + On-prem ApplianceB2B 판매, PoC 운영 쉬움운영/보안/지원 체계 필요

08. 데이터·보안·거버넌스 설계

Tenant Boundary

고객사별 DB schema, 파일 저장소, 벡터 인덱스, 시크릿 네임스페이스 분리.

Permission Boundary

Agent Capability Manifest로 도구별 read/write/destructive 권한 분리.

Approval Boundary

외부 전송, 파일 수정, 결제, 배포, 고객 응답은 위험도 기반 승인.

Audit Trail

누가/언제/어떤 지시/어떤 도구/어떤 결과를 만들었는지 불변 로그.

Secret Store

로컬 Keychain 또는 Vault 호환 저장. 로그/응답에는 토큰 절대 노출 금지.

Data Residency

제조업/공공/민감 고객은 온프레미스 모드, 외부 모델 호출 여부 정책화.

11. MVP 데모 시나리오

  1. 관리자가 bindery-box init manufacturing-demo 실행.
  2. 회사명, 브랜드 컬러, Mattermost 주소, 로컬 문서 폴더 지정.
  3. Mission Control이 열리고 AI 직원 조직도가 표시됨.
  4. Mattermost에 #production, #sales, #scope3, #approvals 채널 자동 생성.
  5. Production Agent가 생산일보 CSV를 읽고 납기 위험 3건을 보고.
  6. Sales Agent가 고객 문의 메일/문서 기반 견적 초안 생성.
  7. Scope 3 Agent가 거래처별 탄소 데이터 누락률과 고객 제출 초안을 생성.
  8. 승인 센터에서 인간 관리자가 외부 전송 전 승인.
  9. 최종 감사 로그와 KPI 개선 추정치가 대시보드에 남음.

12. 더 좋은 방법: “서비스 3단 분리”

Open Core

GitHub 공개판. 로컬 데모, 템플릿, 커넥터 기본형, 문서 중심. 커뮤니티와 신뢰 확보.

Managed Cloud

호스팅형 Mission Control, 데모/PoC 운영, 고객사별 테넌트. 빠른 영업에 유리.

On-prem Appliance

제조업·공공·민감 데이터 고객용. 내부망 설치, 유지보수, SI/컨설팅 매출.

처음부터 Electron 라이브 서비스만 만들기보다, Open Core + Hosted Demo + On-prem Package를 동시에 고려한 구조가 더 좋다. 데스크톱 앱은 설치 경험을 좋게 만드는 껍데기고, 핵심은 Runtime/Office/Web의 분리다.
