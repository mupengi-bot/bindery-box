Product Development Plan · 2026.06.13 · v0.1

BINDERY BOX
/ MUFI Box

Mattermost Office + Mission Control Web + Local Agent Runtime + Desktop Launcher로 구현하는 AI Company-in-a-Box 공식 서비스 개발계획서.

목표는 “CLI 데모”가 아니라 고객이 눈으로 이해하는 소규모 AI 회사 운영 플랫폼이다. 에이전트는 직원처럼 보이고, 업무는 티켓/승인/로그/지표로 남으며, 고객 데이터는 기본적으로 로컬·사내망에 머문다.

1. 제품 구성 강화안

기존 “여러 봇이 돌아간다”를 넘어서, 고객에게는 사무실·관리실·직원·기억·감사체계가 한 번에 설치되는 공식 서비스로 보여줘야 한다.

① Mattermost Office

에이전트가 직원처럼 채널에 상주. 업무 요청, 파일 공유, 승인, 보고가 모두 대화형으로 발생.

고객이 즉시 이해하는 “회사 사무실” UI.

② Mission Control Web

조직도, 현재 업무, 승인 대기, 위험 알림, KPI, 실행 로그를 한 화면에서 관제.

영업/데모의 핵심 화면.

③ Local Agent Runtime

실제 도구 실행, 파일 접근, 커넥터, 스케줄러, 정책 엔진, 감사 로그를 담당하는 백엔드.

제품의 실질적 두뇌.

④ Knowledge Graph

문서, 고객, 프로젝트, 결정, 회의, 코드, 이슈, 계약을 연결하는 회사 기억.

Obsidian 감성은 참고하되 메인 UI는 웹.

⑤ Desktop Launcher

시작/중지/업데이트/로그/권한/시크릿/로컬 폴더 연결을 관리하는 앱.

초기엔 Tauri 권장, Electron은 빠른 프로토타입용.

⑥ White-label Pack

고객사 로고·컬러·도메인·에이전트 이름·산업 템플릿을 바꾸는 패키징 레이어.

공식 서비스/리셀러 확장에 필수.

4. Desktop 앱 설계 — Electron보다 좋은 방법

권장: Tauri 우선

최종 제품은 로컬 권한·시크릿·자동업데이트·트레이 앱이 중요하다. Electron도 가능하지만 용량/메모리/배포 부담이 커서 Tauri + Web UI가 더 깔끔하다.

MVP 웹 코드를 그대로 재사용하면서 앱 크기를 줄일 수 있음.

Electron을 쓰는 경우

초기 내부 데모를 아주 빠르게 만들거나, Node 기반 로컬 제어를 앱 내부에서 무겁게 써야 하는 경우 Electron이 편하다.

공식 배포판은 Tauri 전환을 염두에 두고 설계.

Desktop Launcher 책임 - 로컬 런타임 start/stop/restart - Docker 또는 native service 상태 확인 - Mattermost/Mission Control 열기 - 로컬 폴더 권한 연결 - 시크릿 저장소 관리 - 로그/진단 패키지 생성 - 업데이트 확인 및 롤백 - 고객사 브랜딩 적용 권장 단계 MVP: CLI + Web Alpha: Tauri shell + local API health Beta: signed desktop installer + auto-update v1: customer white-label installer

15. 공식 서비스화 전략

GitHub 공개 전략

처음부터 모든 런타임을 오픈할 필요는 없다. 공식 리포는 제품 소개 + 개발계획 + 데모 스캐폴드로 시작하고, 민감한 운영 코어는 별도 비공개 또는 오픈코어 방식으로 분리한다.

제품 라이선스 전략

초기에는 Apache/MIT보다 source-available 또는 상업 라이선스를 검토. 공개 범위는 템플릿/문서/SDK/데모 앱부터 시작한다.

고객 데모 전략

“설치하면 작은 AI 회사가 생긴다”를 5분 안에 보여준다. Mattermost 사무실 → Mission Control → 제조업 업무 완료 보고 순서.

수익화 전략

PoC 구축비 + 월 구독 + 커넥터 개발비 + 온프레미스 유지보수. 제조업/ESG/영업 자동화 패키지를 첫 상품으로 묶는다.
